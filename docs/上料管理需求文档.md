# 上料管理模块需求文档

## 1. 需求背景

### 1.1 业务场景

SMT 车间的上料（Feeding）是生产准备阶段的核心环节。物料到达车间后，需要先登记入库存档（创建物料批次），再在生产时根据 BOM 清单扫码上料到对应工位。当前上料管理页面仅有"补料"功能，已扩展为完整的两步流程：

1. **物料批次管理**：物料入库时，为每批物料创建 `smt_material_lots` 记录
2. **上料操作**：生产时操作员根据 BOM 清单，直接选择工站并扫码上料物料批次

同时，配套的**下料管理**功能也已上线，支持上料错误或进站失败后的物料撤销操作。

### 1.2 现有问题

- 当前上料管理仅支持"补料"，缺少物料批次建档功能
- 批次/进站/出站接口不可用，需要 Mock 数据兜底
- 上料时未校验物料有效期、状态、剩余数量等

### 1.3 目标

- 在 `LoadingView.vue` 中实现 Tab 切换的两大功能区域
- Mock 数据优先，确认无误后切换真实接口
- 上料时集成 `smt_material_lots` 校验流程
- 上料流程简化为「选择工站 → 扫码上料」，去掉繁琐的批次选择步骤

### 1.4 功能关联

```
┌───────────────────────────────────────────────────────────────────────┐
│                       生产执行模块导航                                 │
├───────────────────────────────────────────────────────────────────────┤
│  上料管理 → 下料管理 → 进站管理 → 出站管理 → 维护管理                     │
└───────────────────────────────────────────────────────────────────────┘

上料管理与下料管理互为逆操作：
- 上料：将物料批次绑定到工站（写入 smt_loading_records）
- 下料：撤销已上料记录（写入 smt_unloading_records，关联原上料记录 ID）
```

## 2. 数据模型

### 2.1 新增表：smt_material_lots（物料批次表）

| 字段                | 类型                           | 说明                             |
| ----------------- | ---------------------------- | ------------------------------ |
| Id                | BIGINT PK AUTO_INCREMENT     | 主键                             |
| MaterialCode      | VARCHAR(50) NOT NULL         | 物料编码（FK → smt_materials）      |
| BatchNo           | VARCHAR(50) NOT NULL         | 批次号（业务唯一，日期+流水号）               |
| Supplier          | VARCHAR(100)                 | 供应商                            |
| SupplierBatchNo   | VARCHAR(50)                  | 供应商批次号                         |
| Quantity          | INT NOT NULL                 | 入库总数量                          |
| UsedQuantity      | INT NOT NULL DEFAULT 0       | 已使用数量                          |
| RemainingQuantity | INT 计算列                    | 剩余数量 = Quantity - UsedQuantity |
| ProductionDate    | DATE                         | 生产日期                           |
| ExpiryDate        | DATE                         | 有效期（锡膏等有有效期）                   |
| MslLevel          | INT                          | MSD 湿敏等级（IC 用）                 |
| InboundDate       | DATETIME(3) NOT NULL         | 入库日期                           |
| Status            | VARCHAR(20) DEFAULT '在库'     | 在库/已使用/已冻结/已报废                 |
| Barcode           | VARCHAR(100) NOT NULL UNIQUE | 条码（自动生成：物料编码#批次号）              |

**状态枚举：**

- `在库`：可用于上料
- `已使用`：全部数量已消耗
- `已冻结`：质量问题冻结中，不可使用
- `已报废`：过期/损坏报废

### 2.2 物料与物料批次的关系

**核心规则：** 一个物料批次只能属于一个物料，但同一物料可以拥有多个批次。

```
物料 (smt_materials)              物料批次 (smt_material_lots)
┌────────────────────┐            ┌─────────────────────────────────────┐
│ MaterialCode  │ 名称 │            │ Id │ MaterialCode │ BatchNo  │ 数量  │
├────────────────────┤            ├─────────────────────────────────────┤
│ R0603-10K    │ 电阻 │◄──┐        │ 1  │ R0603-10K  │ LOT-001 │ 3000 │
│ C0402-10uF   │ 电容 │   │        │ 2  │ R0603-10K  │ LOT-002 │ 2000 │
│ U-QFN32-MCU  │ MCU  │   │        │ 3  │ C0402-10uF │ LOT-003 │ 1500 │
└────────────────────┘   │        │ 4  │ U-QFN32-MCU│ LOT-004 │  600 │
                         │        └─────────────────────────────────────┘
                         │                 ▲
                         │                 │
                         └── 外键关联 ─────┘
                    一个物料批次只能属
                    于一个物料（MaterialCode）
```

**业务含义：**

- **物料**是"品种"（如电阻 R0603-10K），是物料主数据
- **物料批次**是"具体哪一次入库的那批货"，是物料入库的业务记录
- 同一物料可以有多个批次：今天买一批、明天再买一批，形成两个独立的物料批次
- 每个批次独立管理自己的数量、供应商、有效期、入库时间等信息
- 上料时扫码选择的是**具体的物料批次**，用于精确追溯使用了哪一批采购的物料

**约束规则：**

| 规则             | 说明                             |
| -------------- | ------------------------------ |
| ✅ 一对一（对物料批次而言） | 每个物料批次只对应一个物料（MaterialCode 外键） |
| ✅ 一对多（对物料而言）   | 同一物料可以有多个批次（多次采购入库）            |
| ❌ 不允许          | 一个物料批次对应多个物料                   |
| ❌ 不允许          | 物料批次没有关联物料                     |

### 2.3 关联关系

- `smt_material_lots.MaterialCode` → `smt_materials.MaterialCode`（外键，一个物料批次只能属于一个物料）
- `smt_loading_records` 通过物料编码 + 工站关联物料批次（Barcode 作为扫码凭证）
- `smt_unloading_records` 关联 `smt_loading_records.Id`（下料原因：上料错误/进站失败）
- 物料批次由用户**手动创建**（不是系统自动生成），每入库一批物料，用户就在系统中新建一条物料批次记录

## 3. 功能需求

### 3.1 功能模块 A：物料批次管理

#### 3.1.1 页面布局

- 以 Tab 形式存在于上料管理页面
- 包含两个子 Tab：「物料批次管理」和「上料操作」

#### 3.1.2 物料批次列表

- 展示字段：
  - 条码 Barcode（自动生成，点击可复制）
  - 物料编码 MaterialCode
  - 批次号 BatchNo
  - 供应商 Supplier
  - **供应商批次号 SupplierBatchNo**（供应商侧的批次标识）
  - 数量/已用/剩余（剩余数量绿色高亮，为零时灰色）
  - **生产日期 ProductionDate**
  - 有效期 ExpiryDate（过期显示红色警告 + 过期标签）
  - **入库日期 InboundDate**
  - MSL 等级（徽章样式 M1-M6）
  - 状态（Tag 颜色区分：在库=绿色，已使用=灰色，已冻结=橙色，已报废=红色）
- 查询功能：
  - **基础筛选**：物料编码（下拉）、状态（下拉）、批次号/条码（模糊搜索）
  - **高级筛选**：
    - 供应商（模糊搜索）
    - 有效期范围（日期区间选择器）
    - 入库日期范围（日期区间选择器）
  - 支持查询、重置操作
- 支持操作：
  - 修改状态（在库 → 已冻结/已报废，用于异常处理；已冻结 → 在库 解冻）
- 排序：默认按入库日期倒序

#### 3.1.3 创建物料批次（用户手动操作）

**重要说明：** 物料批次由用户在物料入库时**手动创建**，不是系统自动生成的。每当用户购入一批物料入库，操作人员就需要在此页面手动新建一条物料批次记录。

**字段：**

| 字段 | 类型 | 是否必填 | 说明 |
|------|------|---------|------|
| MaterialCode | 下拉选择（搜索） | 是 | 物料编码，数据来自 smt_materials。一个物料批次只能选择一个物料 |
| BatchNo | **自动展示** | 是 | 从后端 API 获取，前端**不生成**，仅负责展示 |
| Supplier | 文本输入 | 否 | 供应商名称 |
| SupplierBatchNo | 文本输入 | 否 | 供应商批次号（供应商侧的批次标识） |
| Quantity | 数字输入 | 是 | 入库数量，必须 > 0 |
| ProductionDate | 日期选择 | 否 | 生产日期 |
| ExpiryDate | 日期选择 | 否 | 有效期（锡膏等有保存期限的物料） |
| MslLevel | 数字输入 | 否 | MSD 湿敏等级（1-6），暂不实现管控逻辑，仅记录 |
| InboundDate | 日期选择 | 是 | 入库日期 |
| Barcode | **自动展示** | 是 | 从后端返回的条码，前端不生成，仅负责展示 |

**交互规则：**
- 用户**手动点击「新建批次」按钮**打开创建表单（对话框形式）
- 表单按 3 个分组组织，提升信息录入效率：
  - **物料信息**：物料编码（下拉搜索）、入库数量
  - **供应商信息**：供应商名称、供应商批次号
  - **日期与有效期**：入库日期、生产日期、有效期、MSD 湿敏等级
- 选择 MaterialCode 后，自动填充 PackageType、Brand 作为参考信息展示（只读）
- BatchNo 和 Barcode 由后端生成并返回，前端仅展示，不生成
- 提交前校验：MaterialCode 存在、Quantity > 0、InboundDate 必填
- 创建成功后展示后端返回的 BatchNo 和 Barcode，并支持「继续创建」

#### 3.1.4 修改/冻结/报废

- 支持修改 Status：在库 → 已冻结、在库 → 已报废、已冻结 → 在库（解冻）
- 已使用状态不可变更
- 修改状态需要二次确认（ElMessageBox）

### 3.2 功能模块 B：上料操作

#### 3.2.1 职责边界

**上料管理只负责「实际上料校验」，即物料批次本身是否合法。**

```
┌─────────────────────────────────────────────────────────────────┐
│  上料管理（Loading）                                             │
│                                                                 │
│  职责：操作员直接选择工站，扫码上料物料批次，校验物料批次本身是否合法    │
│                                                                 │
│  ✅ 校验内容（四项校验）：                                       │
│  • 封装类型：物料封装是否被工站设备类型支持？                    │
│  • 物料状态：批次状态是否为"在库"？                              │
│  • 有效期：是否在有效期内？                                     │
│  • 库存数量：剩余数量是否 ≥ 上料数量？                          │
│                                                                 │
│  ❌ 不负责：BOM 匹配校验                                        │
│      （那是「进站管理」的职责：批次工序→设备类型→封装类型→BOM）    │
└─────────────────────────────────────────────────────────────────┘
```

#### 3.2.2 页面布局

- 以 Tab 形式存在于上料管理页面
- 页面顶部提供两个快捷操作按钮：
  - **去进站**：跳转到进站管理页面（上料完成后进入进站流程）
  - **去下料**：跳转到下料管理页面（上错料时直接进入下料纠正）
- 流程分为 **2 步**：选择工站 → 扫码上料（支持多物料批次同时上料）
- **不再需要先选择批次**：用户直接基于工站进行上料，物料批次条码通过下拉选择或手动输入
- 上料记录记录 `RouteStepId`（工站），精确追溯到具体工位

#### 3.2.3 上料操作流程（支持多批次上料）

**步骤 1：选择工站**
- 以卡片形式展示所有工艺路线工站（按 Sequence 排序）
- 每个工站卡片展示：
  - 序号 + 工站编号（如「1 ST-A1-01」）
  - 工序标签（如「印刷」、「SPI 检测」、「贴片」）
  - 工站名称（如「印刷工站」）
  - 设备类型（如「贴片机」）
- 点击选中某个工站（高亮样式，支持点击切换）

**步骤 2：上料录入（支持多批次同时上料）**

- 选中工站后，顶部展示当前上下文信息条：工站 / 工序 / 设备类型
- **支持两种条码输入方式：**
  - **方式一：下拉选择** 从预设的物料批次条码列表中选择（仅展示在库状态的批次）
  - **方式二：手动输入** 在文本框中手动填写条码信息
- **支持多批次上料**：
  - 用户可点击「新增上料记录」添加多行
  - 系统对每个物料批次独立进行校验
  - 提交上料信息
- 表单字段（每行一个批次）：
  - 输入方式（下拉选择 / 手动输入，Radio 切换）
  - 物料批次条码（下拉选择 或 手动输入）
  - 上料数量（数字输入）
  - 操作人（下拉选择）
  - 校验按钮（手动触发或在条码变更时自动校验）

- **上料校验（每个批次独立校验，四项必须全部通过）：**

| 校验项 | 校验逻辑 | 失败处理 |
|--------|----------|----------|
| **封装类型校验** | 当前批次物料的封装类型是否在该工站设备类型支持的封装列表中 | 阻止上料，显示不匹配原因 |
| **物料状态校验** | 物料批次状态是否为「在库」（排除：已使用、已冻结、已报废） | 阻止上料，显示当前状态 |
| **有效期校验** | 物料批次是否在有效期内（ExpiryDate > 当前日期） | 阻止上料，显示过期日期 |
| **库存数量校验** | 物料批次剩余数量（Quantity - UsedQuantity）是否 ≥ 上料数量 | 阻止上料，显示剩余数量与需求数量 |

- **校验通过后展示：**
  - ✅ 绿色成功面板，展示物料编码 + 描述、批次号 / 供应商、入库数量 / 已使用 / 剩余、有效期、MSL 等级
- **校验失败时触发报警：**
  - ❌ 红色错误面板，带 shake 动画 + 具体错误原因
- 点击「提交上料」→ 一次性写入多个 `smt_loading_records`，同时扣减对应 `smt_material_lots` 的 `UsedQuantity`
- **提交前二次库存校验**：即使校验通过的行也会在提交时重新比对库存，防止校验后库存被其他操作扣减导致数据不一致

**MSD 等级管控说明：**
- 当前阶段**暂不实现** MSD 等级管控相关功能
- 界面上预留 MSL 等级的展示位，仅做信息记录和展示
- 后续可扩展：干燥时间校验、MSD 报警等功能

#### 3.2.4 数据关系说明

```
工艺路线 (Route)
  └── 工序步骤 1 (RouteStep: Sequence=10)
        ├── 工序 (Operation: 印刷)
        ├── 工站 (Station: ST-A1-01 印刷工站)
        └── 设备 (Equipment: PRT-A1-01)
  └── 工序步骤 2 (RouteStep: Sequence=20)
        ├── 工序 (Operation: SPI 检测)
        ├── 工站 (Station: ST-A1-02 SPI 工站)
        └── 设备 (Equipment: SPI-A1-01)
  └── ...（更多工序步骤）

上料记录 (LoadingRecord)
  ├── RouteStepId → 关联工序步骤（确定是哪个工站的上料）
  └── MaterialLotBarcode → 关联物料批次（扫码凭证）

下料记录 (UnloadingRecord)
  ├── LoadingRecordId → 关联原上料记录
  ├── Reason → 下料原因（上料错误 / 进站失败 / 其他）
  └── Remark → 备注
```

#### 3.2.5 校验失败的提示场景

| 校验项 | 场景 | 提示信息 |
|--------|------|----------|
| **封装类型校验** | 物料封装类型不被设备支持 | ❌ 封装类型不匹配：物料 {code} 的封装 {pkg} 不被当前工站设备类型支持 |
| **物料状态校验** | 条码不存在 | ❌ 条码无效，请先在「物料批次管理」中创建物料批次 |
| **物料状态校验** | 状态非"在库" | ❌ 物料批次状态为「已冻结/已使用/已报废」，无法上料 |
| **有效期校验** | 已过期 | ❌ 物料批次已过期（{日期}），无法上料 |
| **库存数量校验** | 剩余数量不足 | ❌ 物料批次剩余 {N}，不足需要的 {M} |

**报警触发机制：**
- 所有校验失败均触发**视觉报警**：红色面板 + 错误图标 + shake 动画 + 具体原因描述
- 单个批次校验失败仅阻止**该批次**的上料，不影响其他已通过校验的批次
- 批量提交时，系统自动过滤掉校验失败的批次，仅提交校验通过的批次

#### 3.2.6 物料批次信息展示（校验通过后）
校验通过后在行内展示：
```

   🔢 库存校验：✅ 剩余 1800，满足上料需求 500

   物料编码：R0603-10K（0603 10K 1% 电阻）

   供应商：Yageo

   有效期：2026-12-31
   MSL 等级：1
```

#### 3.2.7 工站已上料记录查看

在「② 上料录入」区域的右上角提供「查看工站已上料记录」按钮，点击后弹出对话框展示：

- **摘要信息卡片**：工站名称 | 上料记录数 | 上料总量
- **记录表格字段**（9 列，与下料管理可下料记录表保持一致）：
  - 物料批次条码（可复制）
  - 物料编码
  - 批次号
  - 封装类型
  - 供应商
  - 上料数量
  - 校验状态（Tag 标识）
  - 操作人
  - 上料时间
- 数据来源：从 `smt_loading_records` 中按 `RouteStepId` 筛选
- 支持查看历史已上料的完整信息，便于核对和追溯

#### 3.2.8 与下料管理的关联

上料操作与下料管理（`UnloadingView.vue`）形成配对：

- 上料成功后，数据写入 `smt_loading_records`，同一工站的下料操作可基于此记录进行撤销
- 下料操作支持两种场景：
  - **上料错误**：物料批次扫码错误，需撤销上料记录
  - **进站失败**：BOM 校验未通过，需将已上料物料退回
- 下料管理中的「查看工站上/下料记录」可同时查询上料与下料的完整历史

## 4. 接口设计

### 4.1 物料批次接口

| 方法   | 路径                              | 说明                                        |
| ---- | ------------------------------- | ----------------------------------------- |

### 5.4 权限回退策略

由于后端权限数据可能未初始化完整，前端实现回退授权机制：

```javascript
// 拥有 LOADING 权限的用户自动获得 UNLOADING 权限
if (codes.has(PERMISSION_CODES.LOADING) && !codes.has(PERMISSION_CODES.UNLOADING)) {
  codes.add(PERMISSION_CODES.UNLOADING)
}
```

该策略确保上料管理人员同时具备下料管理的访问权限，即使后端 `smt_functions` 表中未配置独立的 UNLOADING 权限码。

## 8. 已明确的实现要求

以下问题已根据用户需求明确：

1. ✅ **批次号生成规则**：前端无需实现批次号生成逻辑，仅需从后端 API 获取后展示
2. ✅ **条码格式处理**：支持两种方式——下拉选择预设条码 + 手动输入条码
3. ✅ **上料校验机制**：实现四项校验（封装类型、物料状态、有效期、库存数量），校验失败触发视觉报警并阻止上料
4. ✅ **多批次上料**：支持同时处理多个物料批次，系统独立校验每个批次，批量提交
5. ✅ **MSD 等级管控**：当前阶段暂不实现，仅预留展示接口
6. ✅ **流程简化**：上料流程由「批次 → 工站 → 扫码」简化为「工站 → 扫码」，提升操作效率
7. ✅ **手动创建物料批次**：物料批次由用户手动创建，非系统自动生成
8. ✅ **下料联动**：下料管理作为上料的逆操作，支持两种下料场景（上料错误 / 进站失败）
9. ✅ **权限回退**：拥有 LOADING 权限的用户自动获得 UNLOADING 权限
10. ✅ **页面快捷按钮**：上料管理页面顶部提供「去进站」和「去下料」两个快捷跳转按钮
11. ✅ **提交前二次校验**：批量提交上料时重新比对库存，防止校验后库存被其他操作扣减
12. ✅ **设备类型标签**：工站卡片和上下文信息条中统一使用「设备类型」标签（字段 equipmentTypeName）
