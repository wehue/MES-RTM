# 进站管理需求文档

## 1. 概述

### 1.1 文档目的
本文档描述 MES-RTM 系统中「进站管理」模块的功能需求、数据结构、校验逻辑和开发任务。重点说明 BOM 匹配校验的实现路径。

### 1.2 模块定位
- **所属模块**：生产执行
- **页面路径**：`/execution/check-in`
- **对应视图**：`src/views/execution/CheckInView.vue`

### 1.3 职责边界

```
┌─────────────────────────────────────────────────────────────────┐
│  进站管理（Check-In）                                            │
│                                                                 │
│  职责：批次进站时，校验该工站的上料是否符合 BOM 要求              │
│                                                                 │
│  ✅ 校验内容：                                                   │
│  • 批次状态是否允许进站                                          │
│  • 当前工序状态是否为"待进站"                                    │
│  • 上一工序是否已完成                                            │
│  • 工站是否绑定设备                                              │
│  • BOM 匹配校验（核心！）                                        │
│                                                                 │
│  ❌ 不负责：物料批次本身的校验                                    │
│      （那是「上料管理」的职责：条码→状态→过期→库存）               │
└─────────────────────────────────────────────────────────────────┘
```

## 2. BOM 匹配校验（核心）

### 2.1 校验逻辑概述

```
┌─────────────────────────────────────────────────────────────────┐
│  BOM 匹配校验流程                                                │
│                                                                 │
│  步骤 1：获取批次当前工序的 RouteStep                            │
│    → RouteStep.EquipmentTypeId = 3 (贴片机)                    │
│                                                                 │
│  步骤 2：查询设备类型支持的封装类型                              │
│    → smt_equipment_package_types WHERE EquipmentTypeId = 3      │
│    → 结果：贴片机支持 [0402, 0603, 0805, QFN32, BGA256]        │
│                                                                 │
│  步骤 3：获取上料记录中的物料封装类型                            │
│    → smt_loading_records WHERE LotId = ? AND RouteStepId = ?    │
│    → JOIN smt_material_lots ON MaterialLotBarcode                │
│    → JOIN smt_materials ON MaterialCode                         │
│    → 获取每个已上物料的 PackageTypeId                           │
│                                                                 │
│  步骤 4：检查已上物料的封装类型是否都在支持列表中                │
│    → ✅ 所有已上物料封装类型都匹配 → 通过                        │
│    → ❌ 有物料封装类型不匹配 → 校验失败                          │
│                                                                 │
│  步骤 5（可选）：BOM 齐套性校验                                  │
│    → 检查 BOM 中所有需要的物料是否都已上料                       │
│    → ✅ 全部齐套 → 通过                                         │
│    → ❌ 有缺失 → 提示缺料                                       │
└─────────────────────────────────────────────────────────────────┘
```

### 3.3 校验规则

#### 3.3.1 基础校验（当前已实现）

| 校验项 | 规则 | 失败提示 |
|--------|------|----------|
| 批次状态 | 必须为"待生产(1)"或"生产中(3)" | 批次已锁定/暂停，需先处理 |
| 工序状态 | 必须为"待进站(1)" | 当前工序不是待进站状态 |
| 上一工序 | 必须已完成（已出站） | 上一工序未完成，无法进站 |
| 设备绑定 | 工站必须绑定设备 | 当前工站未绑定设备 |

#### 3.3.2 BOM 匹配校验（本次新增）

| 校验项 | 规则 | 失败提示 |
|--------|------|----------|
| 获取设备类型 | 从 RouteStep 获取 EquipmentTypeId | - |
| 查询支持的封装 | 从 smt_equipment_package_types 获取支持列表 | - |
| 获取已上物料封装 | 从 loading_records + material_lots + materials 获取 | - |
| 封装类型匹配 | 已上物料的 PackageTypeId 必须在支持列表中 | 物料 {code} 封装 {pkg} 不被设备类型支持 |

#### 3.3.3 BOM 齐套校验（可选）

| 校验项 | 规则 | 提示 |
|--------|------|------|
| BOM 物料清单 | 获取产品 BOM 中该工序需要的所有物料 | - |
| 已上料清单 | 获取当前工序已上料的物料 | - |
| 对比 | 检查 BOM 物料是否都已上料 | ⚠️ 仍有 N 个物料未上料 |

### 6.3 校验函数逻辑（伪代码）

```javascript
async function validateBomMatch(lotId, routeStepId, equipmentTypeId) {
  // 1. 获取设备类型支持的封装类型
  const supportedPackages = await getSupportedPackages(equipmentTypeId)
  // 示例：['0402', '0603', 'QFN32', 'BGA256']

  // 2. 获取当前工序的上料记录
  const loadingRecords = await getLoadingRecords(lotId, routeStepId)
  // 每条记录包含：materialCode, quantity, packageType

  // 3. 检查每条上料记录的封装类型是否在支持列表中
  const results = loadingRecords.map(record => {
    const isSupported = supportedPackages.includes(record.packageType)
    return {
      ...record,
      isSupported,
      status: isSupported ? 'pass' : 'fail'
    }
  })

  // 4. 汇总结果
  const failedItems = results.filter(r => !r.isSupported)
  return {
    supportedPackages,
    loadedItems: results,
    failedItems,
    passed: failedItems.length === 0,
    message: failedItems.length === 0 
      ? 'BOM 匹配校验通过' 
      : `有 ${failedItems.length} 个物料封装类型不被设备支持`
  }
}
```

## 9. 待确认问题

1. **BOM 齐套校验是否阻塞进站？**
   - 方案 A：必须全部齐套才能进站（严格）
   - 方案 B：允许部分上料，但提示缺料（宽松）

2. **BOM 校验的执行时机？**
   - 方案 A：选中批次时实时校验（体验更好）
   - 方案 B：点击提交时才校验（性能更好）

3. **多工序上料的校验范围？**
   - 只校验当前工序的上料记录
   - 还是校验该批次所有工序的上料记录？

4. **已上料但未匹配的物料如何处理？**
   - 阻止进站，要求先撤销不匹配的上料
   - 允许进站但标记异常
