# 下料管理功能设计文档

> 本文档在下料管理功能开发前完成评审，确认后再进行技术实现。

## 1. 需求背景

### 1.1 业务场景

SMT 车间的下料（Unloading）是上料操作的逆向纠正机制。在生产过程中，可能因以下原因需要将已上到工站的物料卸下：

- **上错料场景**：操作员完成上料后发现物料编码、批次或封装类型错误，需要通过下料管理把错误物料卸下后重新上料。
- **校验错误场景**：进站时 BOM/校验失败（如封装不匹配、物料过期等），系统应引导用户先进行下料、再重新上料。

下料管理与上料管理联动，记录每个工站上料与下料的完整历史，便于追溯与纠正。

### 1.2 目标

- 设计与上料管理联动的下料管理功能模块
- 梳理上料、进站、出站、下料四个环节的业务关系及数据流转规则
- 提供工站直接选择 + 下料操作的完整页面交互
- 扩展"查看工站已上料记录"功能，使其同时展示上料与下料记录

## 2. 业务关系与数据流转

### 2.1 四环节业务关系

```
┌────────────────────────────────────────────────────────────────────────┐
│                         生产执行四环节                                  │
│                                                                        │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐         │
│   │  上料    │ →  │  进站    │ →  │  出站    │ →  │  下料    │         │
│   │ Loading  │    │ CheckIn  │    │ CheckOut │    │Unloading │         │
│   └────┬─────┘    └────┬─────┘    └────┬─────┘    └────┬─────┘         │
│        │               │               │               │               │
│        │               │               │               │               │
│   物料批次校验     批次进入工站      批次离开工站     卸下工站物料       │
│   写入上料记录     写入进站记录      写入出站记录     写入下料记录       │
│   扣减物料库存     更新批次工序状态  更新批次工序状态  恢复物料库存       │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.2 数据流转规则

| 环节 | 触发时机 | 数据写入 | 库存影响 | 关联关系 |
|------|----------|----------|----------|----------|
| **上料** | 操作员选择工站并扫码上料 | `smt_loading_records` 新增 | `smt_material_lots.UsedQuantity` 增加 | 关联工站、设备、物料批次、操作人 |
| **进站** | 批次进入工站开始加工 | `smt_station_in_records` 新增 | 无影响 | 关联批次、工站、操作人 |
| **出站** | 批次加工完成离开工站 | `smt_station_out_records` 新增 | 无影响 | 关联批次、工站、操作人、合格/不良数量 |
| **下料** | 操作员选择工站并卸下已上物料 | `smt_unloading_records` 新增 | `smt_material_lots.UsedQuantity` 减少（回退） | 关联上料记录 ID、工站、物料批次、下料原因、操作人 |

### 2.3 四环节时序关系

```
时间轴 →

T1: 上料（物料批次 A 上到工站 ST-A1-03）
    │
    │  ← 若发现上错料：直接进入下料流程
    │
T2: 下料（卸下物料批次 A）
    │
T3: 上料（物料批次 B 上到工站 ST-A1-03）
    │
T4: 进站（批次进入工站加工）
    │
    │  ← 若进站校验失败：引导下料后重新上料
    │
T5: 下料（卸下物料批次 B）
    │
T6: 上料（物料批次 C 上到工站）
    │
T7: 进站（重新进入工站）
    │
T8: 出站（批次加工完成离开工站）
```

### 2.4 触发下料的两种典型场景

#### 场景 A：上错料纠正

```
1. 操作员在「上料管理」完成上料（物料批次 A）
2. 操作员发现物料错误（编码/批次/封装不匹配）
3. 操作员进入「下料管理」
4. 选择同一工站 → 系统展示该工站已上料记录
5. 选择需要卸下的上料记录 → 填写下料原因（4-其他），在备注中说明"上错料"
6. 提交下料 → 系统写入下料记录，恢复物料批次 A 的库存
7. 操作员返回「上料管理」重新上正确物料
```

#### 场景 B：进站校验失败纠正

```
1. 操作员在「进站操作」提交进站
2. 系统校验失败（如 BOM 不匹配、物料过期）
3. 系统提示："校验失败，请先下料后重新上料"
4. 操作员进入「下料管理」
5. 选择对应工站 → 选择需要卸下的上料记录
6. 填写下料原因（4-其他），在备注中说明"进站校验失败"→ 提交下料
7. 操作员返回「上料管理」重新上料
8. 重新进站
```

## 3. 数据模型

### 3.1 数据库表：smt_unloading_records（下料记录表）

> 字段定义对齐实际数据库 `smt_mes.sql1.sql`，已与数据库表结构核对一致。

| 字段 | 类型 | 是否必填 | 说明 |
|------|------|----------|------|
| Id | bigint PK AUTO_INCREMENT | 是 | 主键 |
| LoadingRecordId | bigint NOT NULL | 是 | 关联上料记录 ID（FK → smt_loading_records.Id） |
| LotId | bigint NOT NULL | 是 | 批次 ID（逻辑关联 smt_lots.Id） |
| RouteStepId | bigint NOT NULL | 是 | 工序步骤 ID（逻辑关联 smt_route_steps.Id，确定工站） |
| EquipmentId | bigint NOT NULL | 是 | 设备 ID（逻辑关联 smt_equipment.Id） |
| MaterialId | bigint NOT NULL | 是 | 物料 ID（逻辑关联 smt_materials.Id） |
| UnloadingTime | datetime NULL | 否 | 下料时间 |
| OperatorId | bigint NOT NULL | 是 | 下料操作员 ID（逻辑关联 smt_users.Id） |
| Reason | tinyint NULL | 否 | 下料原因：1-批次完工换线 / 2-物料耗尽 / 3-品质异常 / 4-其他 |
| UnloadQuantity | int NULL | 否 | 下料数量（支持部分下料） |
| InitialQuantity | int NULL | 否 | 初始上料数量（从关联的上料记录获取） |
| ActualUsedQuantity | int NULL | 否 | 实际使用数量（本次生产中实际消耗的物料数量） |
| RemainQuantity | int NULL | 否 | 剩余数量（下料时物料的实际剩余量，CHECK ≥ 0） |
| WastageQuantity | int NULL | 否 | 损耗数量（因抛料/不良等原因造成的损耗） |
| Remark | varchar(200) | 否 | 下料备注（"其他"原因时必填，用户直接填写具体原因） |
| CreatedAt | datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) | 是 | 创建时间 |
| CreatedBy | varchar(50) NOT NULL | 是 | 创建人（从 JWT 自动填充） |
| UpdatedAt | datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE | 是 | 最后修改时间 |
| UpdatedBy | varchar(50) NOT NULL | 是 | 最后修改人 |
| IsDeleted | bit(1) NOT NULL DEFAULT b'0' | 是 | 软删除：0-正常, 1-已删除 |
| LastOperationType | tinyint NOT NULL DEFAULT 1 | 是 | 最后操作：1-新增, 2-修改, 3-逻辑删除 |
| LastOperationRemark | varchar(200) | 否 | 最后操作备注 |

**说明：**
- 数据库无 `StationId` 字段，工站通过 `RouteStepId` 定位（工艺步骤与工站一一对应）
- 数据库无 `MaterialLotId` 字段，物料批次通过 `LoadingRecordId` 间接关联上料记录获取
- `CreatedBy`/`UpdatedBy` 为 varchar(50)（存储用户名），非 bigint
- `IsDeleted` 为 bit(1)，非 tinyint

### 3.2 下料原因枚举（对齐数据库 Reason tinyint）

| Reason Code | 名称 | 说明 | 用户需求场景映射 |
|-------------|------|------|------------------|
| 1 | 批次完工换线 | 批次生产完成后切换产线 | - |
| 2 | 物料耗尽 | 物料批次已全部消耗 | - |
| 3 | 品质异常 | 物料发现质量问题 | 对应"质量异常" |
| 4 | 其他 | 其他原因（**必须填写 Remark 备注**） | 对应"上错料"和"进站校验失败"两种场景 |

**"上错料"和"进站校验失败"两种用户需求场景的处理方式：**
- 数据库 Reason 字段统一归并到 `4-其他`
- 通过 `Remark` 备注字段说明具体场景（如"上错料：物料编码错误，应为 C0402-10uF-B"）
- 选择"其他"原因时下料备注为必填，用户直接在备注文本框中填写具体原因
- 历史记录查询时通过备注文本识别具体场景

### 3.3 与上料记录的关系

```
smt_loading_records（上料记录）           smt_unloading_records（下料记录）
┌──────────────────────────────┐         ┌──────────────────────────────────────┐
│ Id (PK)                      │◄────────│ LoadingRecordId (FK)                 │
│ LotId                        │         │ Id (PK)                              │
│ StationId                    │         │ LotId                                │
│ MaterialLotId                │         │ RouteStepId                          │
│ ActualQuantity (上料数量)    │         │ EquipmentId                          │
│ OperatorId                   │         │ MaterialId                           │
│ LoadingTime                  │         │ UnloadQuantity (下料数量)             │
│ VerifyStatus                 │         │ InitialQuantity (初始上料数量)        │
│                              │         │ ActualUsedQuantity (实际使用数量)     │
│                              │         │ RemainQuantity (剩余数量)             │
│                              │         │ WastageQuantity (损耗数量)            │
│                              │         │ Reason (下料原因 tinyint)             │
│                              │         │ Remark (下料备注)                     │
│                              │         │ OperatorId                           │
│                              │         │ UnloadingTime                        │
└──────────────────────────────┘         └──────────────────────────────────────┘
```

**关联规则：**
- 一条上料记录可以对应多条下料记录（分多次下料）
- 下料数量总和不能超过关联上料记录的 `ActualQuantity`
- 下料时必须引用一个有效的上料记录 ID
- 工站通过 `RouteStepId` 定位（数据库无 StationId 字段）
- 物料批次通过 `LoadingRecordId` 间接关联（数据库无 MaterialLotId 字段）

### 3.4 库存回退规则

下料操作会**回退**物料批次的已使用数量：

```
下料前：smt_material_lots.UsedQuantity = X
下料数量：N（N ≤ 关联上料记录的 ActualQuantity）
下料后：smt_material_lots.UsedQuantity = X - N
```

- 若回退后 `UsedQuantity = 0`，物料批次状态可保持原状态或由用户决定是否改回"在库"
- 若物料批次状态为"已使用"且回退后仍有剩余，状态保持"已使用"
- 下料记录中 `RemainQuantity` 记录下料时物料的实际剩余量（CHECK ≥ 0）

## 5. 接口设计

### 5.1 下料管理接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/unloading/station-records` | 查询工站已上料记录（用于下料选择），参数：`routeStepId`、`stationId` |
| POST | `/api/unloading` | 提交下料，参数：`loadingRecordId`、`unloadQuantity`、`reasonCode`、`remark`、`operatorId` |
| GET | `/api/unloading/list` | 查询下料记录列表，参数：`routeStepId`、`stationId`、`materialLotBarcode`、`startTime`、`endTime` |
| GET | `/api/unloading/station-history` | 查询工站上下料历史（合并上料与下料），参数：`routeStepId`、`startTime`、`endTime` |

### 5.2 提交下料接口详细设计

**POST /api/unloading**

请求参数（字段对齐数据库 smt_unloading_records）：
```json
{
  "loadingRecordId": 1,
  "unloadQuantity": 1200,
  "reasonCode": 4,
  "remark": "上错料：物料编码错误，应为 C0402-10uF-B",
  "operatorId": 3
}
```

**字段说明：**
- `loadingRecordId`：关联的上料记录 ID（必填）
- `unloadQuantity`：下料数量，必须 > 0 且 ≤ 可下料数量（必填）
- `reasonCode`：下料原因 tinyint，1-批次完工换线 / 2-物料耗尽 / 3-品质异常 / 4-其他（必填）
- `remark`：下料备注，"其他"原因（reasonCode=4）时必填，用户直接填写具体原因（如"上错料：物料编码错误"）
- `operatorId`：操作人 ID（必填）

响应：
```json
{
  "id": 1,
  "loadingRecordId": 1,
  "lotId": 1,
  "routeStepId": 103,
  "equipmentId": 3,
  "materialId": 2,
  "unloadingTime": "2026-07-28 15:30:00",
  "operatorId": 3,
  "operatorName": "张工",
  "reason": 4,
  "reasonText": "其他",
  "unloadQuantity": 1200,
  "initialQuantity": 1200,
  "actualUsedQuantity": 0,
  "remainQuantity": 0,
  "wastageQuantity": 0,
  "remark": "上错料：物料编码错误，应为 C0402-10uF-B",
  "materialLotRemainingQuantity": 2000
}
```

**后端处理逻辑：**
1. 校验 `loadingRecordId` 对应的上料记录存在
2. 校验 `unloadQuantity` > 0 且 ≤ 上料记录的 `ActualQuantity` - 已下料数量
3. 校验 `reasonCode` ∈ {1, 2, 3, 4}，若 `reasonCode=4` 则 `remark` 必填
4. 写入 `smt_unloading_records` 记录，字段包括：
   - `LoadingRecordId`、`LotId`、`RouteStepId`、`EquipmentId`、`MaterialId` 从关联上料记录获取
   - `Reason` = reasonCode，`Remark` = remark
   - `UnloadQuantity` = unloadQuantity
   - `InitialQuantity` = 关联上料记录的 ActualQuantity
   - `ActualUsedQuantity` = InitialQuantity - 可下料数量
   - `RemainQuantity` = 可下料数量 - unloadQuantity（CHECK ≥ 0）
   - `WastageQuantity` = 0（暂不计算损耗）
   - `UnloadingTime` = 当前时间
   - `OperatorId` = operatorId
   - `CreatedBy`/`UpdatedBy` 从 JWT 自动填充
5. 回退 `smt_material_lots.UsedQuantity`（减去 `unloadQuantity`）
6. 返回下料记录详情和回退后的物料批次剩余数量

### 5.3 与现有接口的关系

| 现有接口 | 与下料管理的关系 |
|----------|------------------|
| `GET /api/loading/station-records` | 下料管理复用此接口获取工站已上料记录 |
| `PUT /api/loading/supplement` | 上料管理使用，与下料管理互为逆向操作 |
| `POST /api/station-in` | 进站校验失败时引导跳转到下料管理 |

### 6.1 与上料管理的交互

```

│  上料管理    │                    │  下料管理    │
│  LoadingView │                    │UnloadingView │
└──────┬───────┘                    └──────┬───────┘
       │                                   │
       │  写入 smt_loading_records          │
       │  扣减物料批次库存                  │
       │                                   │
       │              ┌─────┐              │
       │              │ 工站 │              │
       │              │ ST- │              │
       │              │ A1- │              │
       │              │ 03  │              │
       │              └──┬──┘              │
       │                 │                 │
       │                 │  读取工站已上料   │
       │                 │  记录            │
       │                 ▼                 │
       │                                   │
       │           写入 smt_unloading_records
       │           恢复物料批次库存         │
       │                                   │
       │  重新上料（写入新上料记录）        │
       │                                   │
```

**交互规则：**
- 上料与下料通过工站（`StationId`/`RouteStepId`）和上料记录 ID（`LoadingRecordId`）关联
- 下料时必须引用一个有效的上料记录
- 下料后物料批次库存恢复，可用于再次上料
- "查看工站已上料记录"功能扩展为"查看工站上下料记录"，合并展示两类记录

### 6.2 与进站管理的交互

```
┌──────────────┐                    ┌──────────────┐
│  进站操作    │                    │  下料管理    │
│ CheckInView  │                    │UnloadingView │
└──────┬───────┘                    └──────┬───────┘
       │                                   │
       │  1. 提交进站                      │
       │  2. BOM 校验失败                  │
       │                                   │
       │  3. 提示用户：                    │
       │  "校验失败，请先下料后重新上料"    │
       │                                   │
       │  4. 提供按钮跳转到下料管理 ────────►│
       │                                   │
       │                                   │  5. 用户完成下料
       │                                   │
       │  6. 用户返回上料管理重新上料       │
       │  7. 重新进站 ◄────────────────────│
       │                                   │
```

**交互规则：**
- 进站校验失败时，前端提示并提供跳转到下料管理的按钮
- 下料管理页面可通过 URL 参数接收工站 ID（如 `/execution/unloading?stationId=3`），自动选中对应工站
- 下料完成后，引导用户返回上料管理重新上料

### 6.3 与出站管理的交互

- 出站管理不直接与下料管理交互
- 出站后批次已离开工站，该工站的上料记录不能再下料（业务约束）
- 下料管理在展示工站已上料记录时，应过滤掉已出站批次对应的上料记录（或标记为"不可下料"）

### 6.4 与批次详情的交互

- 批次详情页可扩展展示该批次关联的上下料记录（可选，后续迭代）
- 当前阶段批次详情已移除"批次上料记录"模块，上下料记录统一在上下料管理页面查看
